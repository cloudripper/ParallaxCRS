What the finder and the patcher actually are as programs: their build phases, their processes, the loop each one runs, and the single gate that decides whether either earns a point. Plus an honest read on whether the upstream work is far enough along to start.

Are we in shape to start

Yes, start now. Everything left on both upstream lists is packaging, interface and enforcement work, not research. Nine days of engineering against known shapes is a schedule; nine days of research would not be. The algorithms that had to be proven are proven: 66 traced databases, every labelled CVE write ranked, no verdict changes.

Two items are research-shaped and can slip. Out-of-bounds read modelling in the static pass, and the calibration of the frontier join's rank axis. Both have working substitutes if they slip, which is what makes starting safe rather than reckless.

02

The finder, as a program

Five build phases produce five artifacts from one source tree. The run phase then starts two independent lanes at second zero, merges three static producers into one ledger, and turns a graph loop that spends model budget only where the join says it is worth spending. Nothing reaches the submission directory that has not first crashed the evaluator's own build.

03

The patcher, as a program

The patcher is a much smaller program with one brutal constraint that shapes everything else: the first diff written to the patches directory is submitted, and submission is final. The template's launcher runs a watcher thread that latches the first file it sees and exits. There is no second attempt, no ranking of candidate patches, no taking the best of three.

So the patcher's real design problem is not how to write a fix. It is how to stop a confident model from writing one before it is verified.

05

Similar to, and different from

Systems in this lineage converge on the same skeleton because the contract forces it: a sanitizer decides truth, an agent drives, and a fuzzer supplies the throughput no agent can match. The differences are narrower than the architecture diagrams suggest, and they are worth naming precisely.

The genuine differentiator

The join, and only the join. Everyone runs a fuzzer and everyone can call a query tool. Almost nobody makes the static rank and the live coverage meet on the same line number and let the result decide where the money goes. That is the one component worth defending in the remaining days.

The unglamorous differentiator

Nothing unverified reaches a submission directory. Scoring multiplies finds by an accuracy term and the patcher submits exactly once. Two gates, each a few lines, protect more points than any analysis improvement available in nine days.

Where we are deliberately ordinary

The loop, the oracle, the engines and the container. All inherited, all unchanged. Every hour spent redesigning a part the template already got right is an hour not spent on the two above, and a divergence that has to be re-tested three times at the freeze.

The risk this table hides. A ledger becomes the agent's whole world: it works on what is in front of it and cannot see what is absent. Three defences are in the design and all three have to survive contact with the schedule. Keep the query-writing branch funded, report per-source counts so an empty taxonomy is visible, and name the unmodelled write classes in the prompt. Drop any one and the ledger quietly becomes a filter.

What has to be true to start tomorrow

Four things, in order. None is analysis work.

Step Owner Done when
Request dataset access today The gated targets are reachable. Everything downstream is unmeasurable without them.
Fork the template, run the sanity target untouched downstream A recorded baseline in both modes: did the stock agent solve either injected bug, and at what cost.
Carve out the fuzzing core, move three rules out of the prompts cc-fuzzer The package installs and advances a recorded state file with no plugin present; a forced unverified promotion is refused; the ledger accounts for every subagent call.
Ship the candidate format cull SARIF the framework validator accepts, flow steps preserved, an offline wheel pinned to the bundled engine, and the crash site inside the top ten candidates on the sanity target.
Start the downstream repo before the upstream work lands. The container wiring can be built against a stub that returns a fixed ledger, and the sooner the baseline exists the sooner every later number means something. Waiting for the upstream packages to be perfect is how nine days becomes four.
